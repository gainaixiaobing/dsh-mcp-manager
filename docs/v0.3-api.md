# dsh-mcp-manager API 契约（Host ↔ Client，v0.4）

> 冻结时间：2026-11-03。Host 半区按此实现；Client 半区（`client.js`）只依赖这里列出的字段，不再猜测。
> 所有 HTTP 都是同源：`GET /mcp-manager/api/state`、`POST /mcp-manager/api/action`。
> v0.3 起请求头必须带 `x-mcp-manager-token: <token>`；token 由 host 通过 index 注入脚本写到
> `window.__MCP_MANAGER_TOKEN__`（字符串）。client 里取 `globalThis.__MCP_MANAGER_TOKEN__ ?? ''`。

```jsonc
{
  "ok": true,
  "servers": [ /* Server 见 §2 */ ],
  "summary": { "total": 0, "uniqueServers": 0, "duplicateServers": 0, "enabled": 0, "disabled": 0,
               "connected": 0, "failed": 0, "notProvisioned": 0, "managed": 0, "toolCount": 0, "orphanToolCount": 0 },
  "storePath": "~/.dsh/mcp-manager/connections-desktop.json",
  "prefsPath": "~/.dsh/mcp-manager/prefs-desktop.json",
  "prefs": { /* 见 §6 prefs 快照 */ },
  "storeError": "可选：受管存储读取失败文本",
  "prefsError": "可选：偏好存储读取失败文本",
  "provisionFailures": { "<serverName>": "错误文本" },
  "toolCount": 298
}
```

## 2. Server 对象

```jsonc
{
  "id": "mcp-manager-qcc-company",   // loader 条目 id（操作主键）
  "shortId": "mcp-manager-qcc-company",
  "origin": "profile" | "managed",
  "serverName": "qcc-company",
  "transport": "streamable-http" | "stdio",
  "endpoint": "https://agent.qcc.com/mcp/company/stream",  // 已脱敏；stdio 只给命令名与参数个数
  "enabled": true,
  "loaded": true,
  "status": "connected" | "disabled" | "no-tools" | "failed" | "not-provisioned",
  "toolCount": 46,
  "toolNames": ["company_search", "..."],   // 永远有
  "tools": [ { "name": "...", "publicName": "mcp__x__y", "description": "..." } ], // 可能为空数组（includeDescriptions=false）
  "duplicate": false,                        // 同名条目 > 1 时为 true
  "error": "可选", 
  "pinned": true, "tags": ["法务"], "note": "内网", // host 已按 serverName 从 prefs 合并，可选
  "lastProbe": { "at": 0, "ok": true, "latencyMs": 120, "toolCount": 46, "errorCode": "可选" } // 有历史才给
}
```

**操作一律传 `server.id`**（不是 serverName）：`config` / `setEnabled` / `probe` / `remove` / `update` / `patchPrefs` 的 `server` 字段都接受 id，`resolveServer` 优先按 id 精确匹配。

## 3. `POST /action`

| method | params | 返回 |
| --- | --- | --- |
| `list` | `{query?, status?}` | `{servers, summary, storePath}` |
| `inspect` | `{server}` | `{server, tools}` |
| `config` | `{server}` | 编辑视图，见 §4 |
| `setEnabled` | `{server, enabled}` | `{changed, persisted, toolCount?, server}` |
| `add` | `{persist?, ...record}` | `{updated, persisted, toolCount, server, storePath}` |
| `update` | `{server, changes}` | `{persisted, server, toolCount?, warning?}` |
| `remove` | `{server}` | `{removed, persisted, serverName, warning?}` |
| `probe` | `{server, timeoutMs?}` | 探针结果，见 §5 |
| `probeMany` | `{servers?, includeDisabled?, concurrency?, timeoutMs?}` | `{total, ok, failed, results: [探针结果]}` |
| `tools` | `{query?, server?, includeSchema?, limit?}` | 工具目录，见 §5b |
| `toolDetail` | `{server, tool}` | `{serverName, toolName, publicName, description, parameters, sampleArguments, status, enabled}` |
| `invoke` | `{server, tool, arguments?, timeoutMs?, dryRun?}` | 调用结果，见 §5c |
| `prefs` | `{}` | `{path, version, updatedAt, ui, servers}` |
| `patchPrefs` | `{server, patch:{pinned?,tags?,note?}}` | `{serverName, prefs}` |
| `setUiPrefs` | `{patch:{autoProbe?}}` | `{autoProbe}` |
| `scan` | `{clients?}` | 同 v0.2 |
| `import` | `{json?, file?, servers?, apply?, onConflict?, enabled?}` | 同 v0.2；`file` 必须来自本会话 scan 结果 |
| `export` | `{format: "patch"|"json"|"markdown"|"diagnostics", server?, servers?, includeProfile?, redact?}` | `{format, content, recordCount, warnings}` |
| `repairStore` | `{backup?}` | `{storePath, servers, backupPath?}`；存储损坏时改名备份后重置 |

`export` v0.3 语义：
- `patch` 默认**只导受管记录**（profile 行已在 cordis.patch.yml 里，再 insert 会重复 id）；
  `includeProfile: true` 才带 profile 行，且会返回 `warnings` 明确提示「覆盖式 patch，不要直接 insert」。
- `json` / `markdown` / `diagnostics` 不受影响；`diagnostics` 是排障报告（不含凭据）。

## 4. `config` 编辑视图（v0.3 新增字段）

```jsonc
{
  "id": "...", "serverName": "qcc-company", "origin": "managed", "transport": "streamable-http",
  "enabled": true,
  "url": "https://agent.qcc.com/mcp/company/stream", // 含凭据时被掩码
  "urlMasked": true,        // true 表示 url 里有凭据被替换为 ***，编辑时留空=保持原值
  "command": "npx", "args": ["-y", "..."], "cwd": "",
  "hasHeaders": true, "headerKeys": ["Authorization"],
  "hasEnv": false, "envKeys": [],
  "toolCallTimeoutMs": 180000,
  "advanced": {
    "reconnect": { "enabled": true, "initialDelayMs": 500, "maxDelayMs": 30000, "maxAttempts": 10 },
    "failOnStartupError": false,
    "maxInstructionBytes": 32768
  }
}
```

`update` 的 `changes` 支持：`url / headers / command / args / env / cwd / toolCallTimeoutMs`，
以及高级项 `reconnect`（浅合并）、`failOnStartupError`、`maxInstructionBytes`。
`url` 传空字符串 = 不改（配合 `urlMasked`）。

## 7. 安全约定（client 必须遵守）

- 所有 fetch 带 `x-mcp-manager-token`（从 `globalThis.__MCP_MANAGER_TOKEN__` 取；拿不到就带空串，
  host 会 401，UI 显示 API 不可用并提示刷新页面）。
- 不在 UI 里持久化任何凭据；`invoke` 结果原样展示（用户主动调用），但复制按钮复制的是文本，不做额外转义。
- 失败/错误文本直接展示（host 已脱敏）。

## 8. 应用归类（v0.4）

把服务按「应用」聚合成组（例如 高德地图 / 同花顺 / 企查查 / 北大法宝）。归类的匹配优先级：
手动覆盖 > 内置目录（serverName 前缀 / URL host / stdio 包名）> URL 域名 > 公共前缀 > 独立服务。

### 8.1 Server 对象新增字段

```jsonc
{
  "app": {
    "id": "fuyao",              // 分组主键（catalog id / host:<domain> / prefix:<p> / server:<name> / manual:<name>）
    "name": "同花顺",            // 展示名（中文）
    "icon": "📈",               // 可选
    "vendor": "同花顺",          // 可选
    "source": "catalog",        // manual | catalog | host | prefix | self
    "singleton": true           // 可选：该应用只有 1 个服务（self 时总是 true）
  }
}
```

### 8.2 `GET /state` 新增 `apps`

```jsonc
"apps": [
  {
    "id": "fuyao", "name": "同花顺", "icon": "📈", "source": "catalog",
    "singleton": false,
    "serverIds": ["mcp-fuyao-a-share", "..."], "serverNames": ["fuyao-a-share", "fuyao-fund"],
    "total": 2, "connected": 2, "failed": 0, "disabled": 0, "noTools": 0, "notProvisioned": 0,
    "toolCount": 40, "pinnedCount": 0, "duplicateCount": 0
  }
]
```

排序：服务数降序 → 应用名升序（host 侧已排好）。

### 8.3 新增 action

| method | params | 返回 |
| --- | --- | --- |
| `apps` | `{}` | `{apps, summary, appCount}` |
| `renameApp` | `{app: <app.id 或 app.name>, name: string\|null}` | `{appId, name, updated, apps}`；`name=null` 清除覆盖恢复自动识别 |

`patchPrefs` 的 `patch` 新增 `app`（字符串 ≤40 字，`null` 清除）。

### 8.4 UI 约定（供实现参考）

- 默认「按应用」视图；两组以上服务的应用显示为可折叠组卡（icon + 名称 + 服务数 + 健康小计 + 工具数），
  单服务应用收进「独立服务」区平铺显示；
- `state.apps` 的顺序即展示顺序；组内行沿用现有 ServerRow（按 pinned → serverName 排序）；
- 组头提供「重命名」与「恢复自动识别」（`renameApp`）；单服务可在编辑面板改「应用归类」（`patchPrefs.app`）；
- 应用筛选 chips 与现有状态筛选、搜索叠加；切换视图/折叠状态属 UI 本地状态。
