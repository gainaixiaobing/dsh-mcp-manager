# v0.5 GitHub 调研：MCP 管理器都在做什么

> 调研时间：2026-11-14。范围：GitHub 上 stars 靠前的通用 MCP 管理器 / MCP 面板，以及 DSH 生态里的同类插件。
> 结论只指导本仓库的设计，不复制代码；所有实现均为本仓库独立编写。

## 一句话结论

v0.2 补的是「能管」（持久化、导入导出、探针），v0.3 补的是「能看能试」（工具中心、试用、健康看板），
v0.4 补的是「看得懂」（按应用归类）。**v0.5 补的是「管得住」**：

1. **体检（doctor）**——在握手失败之前就把配置问题找出来；
2. **Token 账本**——29 个服务、300 个工具时，真正贵的是塞进上下文的 schema；
3. **接入片段**——同一个服务要同时进 Claude Code / Cursor / VS Code / Codex / DSH。

这三件事的共同点：**只读、零副作用、离线可测**，与本插件「只把本机 MCP 管好」的定位一致。

## 逐个看：值得抄的与不该抄的

### mcpm.sh —— `doctor` 与 client integration 是本轮最大启发

- **`mcpm doctor`**：一条命令输出「系统健康 + 每个服务状态」，把用户从「一个个试」里救出来。
- **client integration**：服务装一次，`mcpm client add <client>` 生成各客户端的配置。
- **virtual profiles**：把服务分组，按场景切换。
- 不适用：它是 CLI + 中央注册表模型，服务全局安装；DSH 已经有 profile/loader，本插件不该再发明一层安装目录。

**采纳**：`mcp_manager_doctor`（体检工具 + 面板）、`mcp_manager_snippet`（5 种客户端片段）。
**未采纳**：profiles（DSH 的 profile 已经是这层）、registries。

### mcp-hub —— 占位符解析说明「静默失败」是最大痛点

- 支持 `${VAR}` / `${env:VAR}` / `${input:var}` 多轮解析，缺变量时给出明确错误；
- `/api/health` 暴露 uptime、每个服务的状态与工具数；
- 不做 UI，配置就是 JSON。

**采纳**：体检里的占位符检查（`${VAR}` / `${env:VAR}` / `${input:…}` / `!!js process.env.X`），
把「变量没配」从运行时谜题变成一条 error。

### mcpick —— doctor 可以是一个只读工具

- `mcpick_doctor` 作为 MCP 工具暴露给 agent，读操作带 read-only 注解；
- 输出前按已知 secret 模式脱敏（`env` / `headers` 显示 `***`）；
- 自身能 `serve` 成 MCP server，让 agent 用工具调用而不是 shell 管理配置。

**采纳**：体检做成对话工具（`mcp_manager_doctor`），输出沿用统一的 `sanitize.js` 脱敏出口；
`doctor` 支持 `server` / `severity` / `includeInfo` 收窄，方便 agent 分诊。

### dsh-armory —— 「工具裁缝：谁在吃 token」

- 把每个服务的工具定义折算成 token 占用，指出关掉哪个服务最省上下文；
- 项目级 MCP（`.dsh/mcp.json`）与全局 MCP 分离；
- 升级提示、更新卡片等 DSH 生态惯例。

**采纳**：`mcp_manager_tokens` + 面板里的 token 概览与行内 `~1.2k tok` 徽章。
**未采纳**：项目级 MCP（属于 loader 层能力，不是本插件该改的）。

### Brightwing mcp-manager —— token budget 与「凭据不进配置文件」

- 按 app 做工具过滤并显示 token budget；
- 加密凭据库（Stronghold + OS keychain），配置里只留引用；
- 注册表治理：allowlist + 审批 + 审计日志。

**采纳**：token budget 的展示口径（每个服务多少 token、占多少）。
**未采纳**：加密凭据库（DSH 的信任模型是 0600 明文 + `~/.dsh/.env`，另起一套只会更乱）、
治理/审计（那是企业网关的能力）。

### mcp-dock —— 多客户端同步与「历史回滚」

- 14 个客户端的配置读写、一键安装、同步；
- 配置文件自动备份 + 一键回滚；
- 内置 MCP Inspector 做调试。

**采纳**：多客户端片段的**格式**（Cursor / VS Code / Claude Code / Codex 的字段差异）。
**未采纳**：直接写别的客户端的配置文件——本插件的安全边界是「只读扫描，不写回」。
回滚能力留给「导出 patch + 手动合并」，避免插件替用户改 profile。

### HarnessKit —— 安全审计要能打分、能解释

- 20 条静态规则给出 0–100 信任分，分三档；
- 每条发现能看到「文件路径 / 目录结构 / 审计结论」；
- Kits：把 skills + MCP + rules 打包成可移植套件。

**采纳**：体检的**分级 + 修复建议**结构（error/warn/info，每条给 fix）。
**未采纳**：信任分（本插件的 `riskFlags` 只做客观标记，不替用户下"安不安全"的结论）、Kits（v0.6 候选）。

### inspector / claude-code-tool-manager / amxv

- inspector 的 SchemaForm + Execute 已在 v0.3 借鉴；
- `claude-code-tool-manager` 与 `amxv/mcp-manager` 都验证了「列表 + 启停 + env 编辑」是刚需最小集，
  但都没有解决「为什么起不来」和「占多少上下文」——这正是 v0.5 要补的。

| 能力 | 具体实现 | 来源 |
| --- | --- | --- |

| 体检分级 | `severity: error\|warn\|info` + 每条 `fix` 建议；面板可筛选、可复制报告 | HarnessKit 审计、mcp-hub health |
| Token 账本 | `lib/tokens.js`：按服务/工具估算 schema token，CJK 加权；面板概览 + 行内徽章 + 工具排行 | dsh-armory「工具裁缝」、Brightwing token budget |

| 缺口检测 | `${VAR}`、`${env:VAR}`、`${input:…}`、`!!js process.env.X` 四类引用；PATH 查找可执行文件 | mcp-hub、mcpick |

## 仍然不做（明确划界）

- **不做网关 / 聚合端点**：本插件管的是「已经接入 DSH 的服务」，不是再造一个 MCP router；
- **不做 OAuth 授权流**：需要 OAuth 的服务用 `headers` / `env` 传 token；
- **不做远程注册表浏览器**：v0.5 只做「读一份本地 `server.json` / `mcpServers` JSON」，不联网拉目录；
- **不写别的客户端配置文件**：只生成片段让用户自己粘贴，扫描仍然只读；
- **不做工具级启停**：底层 `dsh-mcp-client` 没有工具过滤字段，伪造这层能力等于骗用户。

## v0.6 候选

- 服务套件（Kit）：内置 starter kit + 空态引导 + 一键批量接入（预览后写入）；
- 官方 MCP Registry `server.json` 导入（离线文件，解析 `packages[].registryType` → command/args 或 oci）；
- 导入向导 v3：应用前快照 + 失败回滚 + 逐条冲突 UI；
- 体检的「一键修复」：能安全自动处理的只有 `store` 修复与 enabled 对齐，其余仍给建议。
